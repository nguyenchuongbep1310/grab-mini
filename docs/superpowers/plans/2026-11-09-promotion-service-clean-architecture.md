# promotion-service Clean Architecture Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `services/promotion-service` from a flat `package main` to `internal/{domain,app,adapters/*,integration}` with the dependency rule enforced by `pkg/archtest`, changing no observable behaviour.

**Architecture:** Fourth service in the ADR 0014 order (after `payment-service`, `trip-service` and `order-service`, all in `main`). Pure rules (`discount.go`, the code and price parsing and the create validation in `api.go`, the redemption decision in `redemption.go`) go to `domain`; the use cases and their ports go to `app`; Postgres, Kafka, HTTP, Prometheus and the promo-token signer become adapters; `main.go` stays the composition root. New packages are added first and nothing calls them until one switch-over task deletes the flat code, so every commit compiles and passes its tests.

**Tech Stack:** Go 1.26 workspace (`go.work`), pgx/v5, kafka-go, Prometheus client, `grab-mini/pkg/{auth,outbox,eventcodec,events,kafkaconsumer,kafkaconn,promo,migrate,archtest,...}`. No Redis: the service does not use it (`grep -rn 'redisconn' services/promotion-service` is empty and must stay empty).

**Spec:** `docs/adr/0014-clean-architecture-for-go-services.md` (layout, dependency rule, "What is explicitly not changed", migration recipe, rollback, and the order-service result with its lessons). Reference shapes: `services/payment-service/internal/`, `services/trip-service/internal/`, `services/order-service/internal/` (read `internal/integration/testdb_test.go` and `internal/arch_test.go` there before Tasks 5, 7 and 8).

## Global Constraints

Copied from the ADR; every task's requirements include them.

- Dependency rule, enforced by `services/pkg/archtest` (`archtest.Default(module).Test(t, ".")` from `internal/arch_test.go`): `domain` imports the standard library only, without `net/http`, `database/sql`, `os` and the other I/O packages in `Rules.StdlibBanned`; `app` imports `domain`, the standard library (same exclusions) and `Rules.AppAllowed` (here unchanged: `github.com/google/uuid` only, Decision 1); neither imports `services/pkg/*`, an I/O library or an adapter; an adapter may import anything except another adapter.
- Not changed:
  - HTTP routes, roles, rate limit, status codes and JSON bodies (each error response's `Content-Type` and exact body bytes, including key order and the trailing newline of `json.Encoder`).
  - Topics, keys (`promotion.redeemed` is keyed by `orderId`), the consumer group, the consumed-topic list and its order, Avro schemas.
  - Tables, constraints, and migration files `00001` and `00002` (none edited, renumbered or moved).
  - Environment variable names and defaults (`SCHEMA_REGISTRY_URL`, `PORT`, `DATABASE_URL`/`DATABASE_URL_FILE`, `KAFKA_BROKERS`, `PROMO_SECRET` through `promo.SignerFromEnv`, the `auth` verifier variables, `RUN_MIGRATIONS`, `APP_ENV`).
  - Metric names, labels and help text of the four counters; log message texts (the runbook quotes `order booked with unknown promotion "CODE"` and `invalid promotion event`; the alerts and runbook name `promotion_validations_total`, `promotion_redemptions_total`).
  - `deploy/`, `scripts/` (`scripts/dev.sh` runs `promotion-service seed-dev`), `docker-compose.yml`, `services/pkg/events`, `services/e2e-test`.
- `main.go`, `env.go` and `migrations/` stay at the service root. `go build .` is what the Dockerfile and `deploy/verify.sh` run; `//go:embed migrations/*.sql` stays in `package main` (a package under `internal/` cannot embed `../../migrations`); the `migrate` and `seed-dev` subcommands keep working.
- The consumer group stays a literal `GroupID: "promotion-service-group"` in a non-test `.go` file: `deploy/k8s/check.py` reads it with `GroupID:\s*"([^"]+)"` over the service's `.go` files (recursive); `deploy/monitoring/alerts.rules.yaml` and KEDA scale on that name.
- Prometheus counters register at package init (`promauto`): exactly one package (`adapters/metrics`) declares each of the four counters. `go test` per package passes while `main` panics on a double registration, so Task 7 also runs the binary.
- Tests:
  - Domain and app tests need no containers.
  - Every Go test package that clears tables gets its own private database (Decision 6); parallel packages share `TEST_DATABASE_URL`, and a shared database makes them wipe each other's rows.
  - No test in this plan refuses `:6379` or calls `FlushDB` (there is no Redis here); do not introduce either.
  - Moved tests keep their names unless a task says otherwise; no test is dropped.
  - Kafka must be freshly recreated before every e2e run (a reused broker poisons the payment-service Kafka tests; known, not fixed here).
- Run containers only with names and host ports that cannot collide with anything else (for example `pm-mig-pg`, `pm-mig-kafka`, ports in `55xxx`), and remove them (`docker rm -f`) when the task is done.
- One service, one pull request, one commit per task. Rollback is `git revert` of this service's commits; nothing in `deploy/` changes.
- Do not fix unrelated bugs: list them in the task report (candidates already seen are in "Known, not fixed").
- Shared repository: before each commit run `git status` and `git log`; stage only your own paths (`git add <paths>`, never `-A`, `-a`, `stash` or `reset --hard`); never push.

## Decisions this plan makes (the executor must not reopen them)

1. **`app` needs no `services/pkg` package at all; `Rules.AppAllowed` is not extended.** What each pkg package the old code touches would mean for `app` (import lists taken with `go list -f '{{join .Imports " "}}'` in `services/pkg/<name>` on main at 88201b7):

   | pkg | direct imports | verdict for `app` |
   |---|---|---|
   | `promo` | `crypto/hmac crypto/sha256 encoding/base64 encoding/json errors grab-mini/pkg/secret strings time` | **Not allow-listed.** It is not import-pure: it imports `pkg/secret`, and `pkg/secret` imports `os` (`errors fmt os strings`). The only call the service makes is `Signer.Issue` (and `promo.Binding`); that goes behind a `TokenIssuer` port, implemented by `adapters/promotoken`. (The order-service plan said `promo` imports only `crypto/*`, `encoding/*`, `math`, `strings`; that was wrong, and ADR 0014 already corrects it. Do not copy it.) |
   | `outbox` | pgx, pgxpool, `prometheus`, `kafka-go`, `pkg/metrics`, `pkg/tracing` | No. It is the Postgres adapter's (`outbox.Add`) and `main`'s (`outbox.NewRelay`). |
   | `eventcodec` | `net/http`, `crypto/tls`, `hamba/avro`, `pkg/events`, `pkg/secret`, `os` | No. Hidden behind the `Encoder` port. |
   | `events` | `embed fmt` | Not imported by `app` (ADR: the wire contract is mapped in the Kafka adapter). A contract test pins the strings the domain copies (Task 6). |
   | `kafkaconsumer`, `auth`, `migrate`, `health`, `serve`, `tracing`, `metrics`, `secret`, `logging` | I/O, HTTP or environment | No. Adapters or `main` only. |

   With the table above, `app` may import: the standard library minus the banned I/O packages, `github.com/google/uuid` (to validate the `eventId` and mint the announced event's id, exactly as the old code does), and `grab-mini/promotion-service/internal/domain`. **Verification, run in Task 8 and again whenever `app` changes:** `go list -f '{{range .Imports}}{{println .}}{{end}}' ./internal/app | grep -E '^(grab-mini|github|golang|google)'` prints exactly `github.com/google/uuid` and `grab-mini/promotion-service/internal/domain`, nothing else. This is a check of **direct** imports, which is also all `archtest` checks (it parses imports of the files under `internal/`, not their dependencies): `github.com/google/uuid` itself imports `net`, `os` and `database/sql/driver`, so a transitive "app is free of I/O" claim is false and is not made. Domain has the same property by construction (standard library only, direct).
2. **`TokenIssuer` is a port with a one-method adapter.** `Issue(code, riderID string, price int64, vehicle string, discount int64, now time.Time) (token string, expiresAt time.Time)`; `adapters/promotoken` wraps `*promo.Signer` and builds the `promo.Binding{RiderID, Price, Vehicle}`. It has two implementations (the real signer and a fake in the app tests) and keeps `pkg/promo` out of `app`. A contract test in the adapter issues a token and verifies it with `promo.NewSigner(sameKey).Verify` (what order-service does), so the token that order-service checks cannot drift.
3. **The redemption and release transactions keep their exact shape and order.** `UnitOfWork.Do(ctx, fn func(Tx) error) error` begins a transaction, runs `fn`, commits when `fn` returns nil and rolls back otherwise (the old `defer tx.Rollback`). Inside `Do`, in this order, as today: the `eventId` UUID check (permanent `InvalidEvent`, before any SQL; it runs in the use case) and `MarkEventProcessed` (the marker insert), `LockOrder` (`pg_advisory_xact_lock(hashtext('promotion-order:'+id))`), then for a redemption `FindPromotionForUpdate` (row lock), `OrderWasCancelled`, `Usage`, `InsertRedemption`, the Avro encode, `outbox.Add`; for a release `ReleaseRedemptions` then, only when it released nothing, `RememberCancelled`. Consequences to keep and pin:
   - The `Encoder` is called **inside** the transaction, while the advisory lock and the promotion row lock are held (the encode depends on whether the insert happened). The ADR's "encode before the transaction" does not apply to this service; preserve the old order, do not "improve" it (see Known, not fixed).
   - An error returned from `fn` rolls everything back, including the `promotion_events` marker: an event refused as permanent (unknown code) leaves no trace so a redrive after the promotion exists still applies it.
   - The "event already processed" path and the "already recorded under another event" path both return nil from `fn` with nothing more to write (the first old path rolled back an empty transaction, the second committed one that holds only the marker). Both are indistinguishable from outside.
   - A duplicate is counted and logged **inside** `fn` (before the commit), as today; the redeemed, over-limit, released counters and their log lines run **after** a successful commit, from values `fn` stored in locals; `Relay.Wake` runs after the commit and only when an outbox row was queued (never for a duplicate, never for the "recorded as released" path).
4. **Metrics live in `adapters/metrics`, behind an `app.Metrics` port.** `Metrics{ Validation(result string); Redemption(status, reason string); Released(n int64); Duplicate() }` (`Redemption` with reason `""` for REDEEMED, as the old `WithLabelValues(status, "")`; `Released(n)` is `Add(float64(n))`). The four counters keep their names, label sets and help text (copy the strings; Task 1 records them, Task 5 compares). The use case calls the port at exactly the points the old code incremented. Log lines stay in the use case through the standard `log` package, character for character.
5. **The use cases take plain types and own the order of refusals.** `Validate` takes the three query strings (`ValidateQuery{RiderID, Code, Price, VehicleType string}`) because the old order is part of the behaviour: shape of the code (counts `not_found` and answers 404) before the price, before the vehicle, before any SQL. The HTTP adapter only extracts the query values and the caller's subject. Create validation (`createRequest.promotion`) becomes `domain.NewPromotion(NewPromotionSpec, now) (Promotion, error)` with the existing message strings. The `events.*` structs never reach `app`: the Kafka adapter maps them to `RedeemOrderCommand`, `ReleaseCommand`; the trip status stays a string in `ReleaseCommand` and the rule "only CANCELLED releases" stays in the use case (`domain.TripStatusCancelled`, pinned to `events.TripStatusCancelled` by a contract test).
6. **Test databases.** The old tests truncate `redemptions, promotion_events, promotion_cancelled_orders, promotions` and `DELETE FROM outbox WHERE source = 'promotion-service'` on `TEST_DATABASE_URL`. After this migration there are three DB-backed test packages (`adapters/postgres`, `integration`, and the root package until Task 7). Each of the two new ones gets a `testdb_test.go` copied from `services/order-service/internal/integration/testdb_test.go` (change the package, the `promotest_<package>_` database prefix, and `migrations()` to `os.DirFS("../..")` or `"../../.."` according to depth; `postgres.Connect` there takes `fs.FS`). Databases are created per test and dropped `WITH (FORCE)`. The root package keeps its old shared-database fixture only until Task 7 deletes it; it cannot collide with the private databases.
7. **Seed.** `seedDev` becomes `postgres.SeedDev(ctx, *pgxpool.Pool) (int, error)` (same SQL, same three rows, `ON CONFLICT (code) DO NOTHING`) in `adapters/postgres/seed.go`. It is a dev command with one caller; it gets no use case and no port. The `APP_ENV=development` guard (`secret.Development()`) and the log text stay in `main.go`.
8. **No repository interface with many methods.** Ports (all declared in `app`, small): `PromotionReader{ Find, Usage }`, `PromotionWriter{ Create, Disable }`, `PromotionViews{ View, List }`, `UnitOfWork`/`Tx`, `Encoder`, `TokenIssuer`, `Waker`, `Metrics`. One `postgres.Store` implements the first three; `postgres.UnitOfWork` implements the fourth.

## Review Focus

Behaviour the ADR implies and the existing tests do not fully pin; each has a test in the owning task.

1. **Error response bytes, exact.** Every refusal goes through `writeJSON`: `Content-Type: application/json`, `json.NewEncoder` output (map keys sorted: `code` before `error`; trailing newline); 401 and 403 come from `auth.Deny` / the verifier. Pinned by a golden table recorded from the old code in Task 1 and asserted again in Task 6.
2. **Order of refusals in validate:** malformed code (404, counted as `not_found`, no DB) before price (400 `invalid_request`) before vehicle (400; `car` in lower case is refused, case-sensitive) before the lookup; an unknown vehicle on the *admin create* has its own message. Pinned in Task 1 (golden) and Task 4 (use case).
3. **Encode inside the transaction, with both locks held, and nothing left behind by a refused event.** Pinned by `TestTheEncodeRunsInsideTheTransaction` (Task 4, fake unit of work that records the order of calls) and the old `TestEventsThatCanNeverBeAppliedArePermanentErrors` (no `promotion_events` row after refusal).
4. **Release and redeem race on one order** (`order.cancelled` before `order.created`, and the reverse, concurrently): the advisory lock is taken before the promotion row lock, before the `promotion_cancelled_orders` read; the old tests (`TestCancellingAndRedeemingAtTheSameTimeNeverLeavesALiveRedemption`, `TestReleasingAndRedeemingAtTheSameTimeNever...`) must run unchanged in Task 7, plus a call-order test in Task 4.
5. **Two clocks.** A redemption recorded for an already-cancelled order stamps `released_at` with the **application clock** (`s.now()`); a normal release stamps it with the **database** clock (`now()` in the `UPDATE`). The announced event's `occurredAt` is `s.now().UTC()` formatted RFC3339Nano and its `eventId` a fresh UUID. All three are preserved (the app passes `Now` in the command to the port; the encoder adapter only formats). Pinned in Task 4/5.
6. **Counters and logs only after a successful commit** (except the duplicate counter and its log). Pinned with a fake unit of work whose commit fails (Task 4): no redeemed counter, no `Wake`.
7. **Typed-nil `Waker`.** The old code checks `s.relay != nil` for a `*outbox.Relay`. A nil `*outbox.Relay` stored in an `app.Waker` is a non-nil interface and would panic. `main` always passes a real relay; tests pass an untyped nil `Deps.Relay`; the use case checks `s.relay != nil`. Do not build a `Waker` from a possibly-nil pointer.
8. **Admin views.** JSON key order is the struct field order; `maxDiscount`, `vehicleType`, `usageLimit`, `disabledAt` are `null` not absent; an empty list is `{"promotions":[]}` not `null`; `status` is computed with the clock at read time; list is newest first (`created_at DESC, code`), limit 500. Pinned in Task 1 with `createdAt` masked, asserted again in Task 6.
9. **Permanent errors keep their type and text.** `invalidEvent` (`invalid promotion event: ...`) reports `Permanent() == true` through `errors.As`; the Kafka consumer sends it straight to the DLQ. The type moves to `app` with the same `Error()` text.

### Task 2: `internal/domain`

**Owner:** go-service-dev.

**Files:**
