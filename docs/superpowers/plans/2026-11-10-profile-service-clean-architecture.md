# profile-service Clean Architecture Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `services/profile-service` from a flat `package main` to `internal/{domain,app,adapters/*,integration}` with the dependency rule enforced by `pkg/archtest`, changing no observable behaviour.

**Architecture:** Fifth service in the ADR 0014 order (after `payment-service`, `trip-service`, `order-service` and `promotion-service`, all in `main`). Pure rules (`validate.go`, the driver state machine inside `store.go`, `nextReviewTime`, the queue cursor and filters, the resync eligibility and dating) go to `domain`; the use cases and their ports go to `app`, **including resync, which is a use case with ports** (Decision 2); Postgres, Prometheus, the Avro-side event mapping and HTTP become adapters; `main.go` stays the composition root and keeps the three subcommands. New packages are added first and nothing calls them until one switch-over task deletes the flat code, so every commit compiles and passes its tests.

**Tech Stack:** Go 1.26 workspace (`go.work`), pgx/v5, kafka-go (producer side only, in `main`), Prometheus client, `grab-mini/pkg/{auth,outbox,eventcodec,events,kafkaconn,migrate,secret,health,serve,tracing,metrics,logging,archtest,...}`. The service **consumes no topic** (no `kafkaconsumer`, no `GroupID`) and uses no Redis: `grep -rn 'GroupID\|kafkaconsumer\|redisconn\|ROUTING_URL' services/profile-service --include='*.go'` is empty today and must stay empty.

**Spec:** `docs/adr/0014-clean-architecture-for-go-services.md` (layout, dependency rule, "What is explicitly not changed", migration recipe, rollback, and the four Result sections with their lessons). Reference shapes: `services/promotion-service/internal/`, `services/order-service/internal/` (read `internal/integration/testdb_test.go` and `internal/arch_test.go` there before Tasks 6, 8 and 9).

## Global Constraints

Copied from the ADR; every task's requirements include them.

- Dependency rule, enforced by `services/pkg/archtest` (`archtest.Default(module).Test(t, ".")` from `internal/arch_test.go`): `domain` imports the standard library only, without `net/http`, `database/sql`, `os` and the other I/O packages in `Rules.StdlibBanned`; `app` imports `domain`, the standard library (same exclusions) and `Rules.AppAllowed` (here unchanged: `github.com/google/uuid` only, Decision 1); neither imports `services/pkg/*`, an I/O library or an adapter; an adapter may import anything except another adapter.
- Not changed:
  - HTTP routes, roles, status codes and JSON bodies: each response's `Content-Type: application/json` **and `Cache-Control: no-store`** (set by `writeJSON` on every response, errors included), the exact body bytes (key order, trailing newline of `json.Encoder`), the `Retry-After` header and `retryAfter` body field of the 429.
  - Topic `driver.application.reviewed`, key `driverId`, Avro schema; the service consumes nothing and still has no consumer group.
  - Tables, constraints, the queue index, migration files `00001` and `00002` (none edited, renumbered or moved).
  - Environment variable names and defaults (`SCHEMA_REGISTRY_URL`, `PORT`, `DATABASE_URL`/`DATABASE_URL_FILE`, `KAFKA_BROKERS`, `PUBLIC_RATE_PER_MINUTE`, `RATE_LIMIT_SCALE`, the `auth` verifier variables, `RUN_MIGRATIONS`, `APP_ENV`).
  - Metric names, labels and help text of all **seven** counters (`profile_updates_total{kind}`, `profile_applications_total{result}`, `profile_reviews_total{decision}`, `profile_requests_rejected_total{reason}`, `profile_public_lookups_total{result}`, `profile_resync_events_total{status}`, `profile_resync_runs_total{result}`); log message texts (the runbook and guide quote the resync, review and vehicle-change lines).
  - **Personal data is never logged.** `driverRow`/`riderRow` carry the comment "PERSONAL DATA: never log one": no new log line, `%+v` or error text may carry a name, phone, plate, model or colour. Logs carry ids only.
  - `deploy/`, `scripts/` (`scripts/dev.sh` runs `profile-service seed-dev`), `docker-compose.yml`, `services/pkg/events`, `services/e2e-test`.
- `main.go`, `env.go` and `migrations/` stay at the service root. `go build .` is what the Dockerfile and `deploy/verify.sh` run; `//go:embed migrations/*.sql` stays in `package main`; the `migrate`, `seed-dev` and `resync [--driver id]` subcommands keep their exact flags, output text, exit codes and `log.Fatal*` texts. `runMigrate`, `runSeedDev` and `runResync` live in `main.go` after the migration (no other root file).
- No consumer group exists, so there is **no `GroupID` literal to preserve**; the check is the reverse: `deploy/k8s/check.py` must still report profile-service as having no consumer group, no Redis use and no routing-service call (Task 1 records, Task 9 compares).
- Prometheus counters register at package init (`promauto`): exactly one package (`adapters/metrics`) declares each of the seven counters. `go test` per package passes while `main` panics on a double registration, so Task 8 also runs the binary (`migrate`, `seed-dev`, `resync`).
- **The flat code is the spec, the plan is not.** Where this plan and the flat code disagree, the flat code wins and the executor says so in the report (promotion-service lesson: the plan said "Wake only when a row was queued", the code woke after every recording commit). Every use case task starts by re-reading the flat function it moves, line by line, and the order of its steps is behaviour: claim/lock order, the clock read point, encode, outbox add, commit, then counters, log, wake.
- Tests:
  - Domain and app tests need no containers.
  - Every Go test package that clears tables gets its own private database (Decision 9); the flat package, `adapters/postgres` and `integration` run in parallel and a shared database makes them wipe each other's rows.
  - No test refuses `:6379` or calls `FlushDB` (no Redis here); do not introduce either.
  - Moved tests keep their names unless a task says otherwise; no test is dropped. **A golden test that is split across layers is accounted for assertion by assertion** (Decision 12).
  - Kafka must be freshly recreated before every e2e run (a reused broker poisons the payment-service Kafka tests; known, not fixed here).
- Run containers only with names and host ports that cannot collide with anything else (for example `pf-mig-pg`, `pf-mig-kafka`, ports in `55xxx`), and remove them (`docker rm -f`) when the task is done.
- One service, one pull request, one commit per task. Rollback is `git revert` of this service's commits; nothing in `deploy/` changes.
- Do not fix unrelated bugs: list them in the task report (candidates already seen are in "Known, not fixed").
- Shared repository: before each commit run `git status` and `git log`; stage only your own paths (`git add <paths>`, never `-A`, `-a`, `stash` or `reset --hard`); never push.

## Decisions this plan makes (the executor must not reopen them)

1. **`app` needs no `services/pkg` package at all; `Rules.AppAllowed` is not extended.** Import lists taken with `go list -f '{{join .Imports " "}}'` in `services/pkg/<name>` on main at 90a9ea2 (a direct-import fact; re-run in Task 9):

   | pkg | direct imports | verdict for `app` |
   |---|---|---|
   | `events` | `embed fmt` | Import-pure, but **not imported by `app` or `domain`**: ADR 0014 keeps the wire contract in the adapter. `events.VehicleType` is what `validate.go` and `driverRow` use today; domain gets its own `VehicleType` (string, `Valid()`, `VehicleCar`, `VehicleBike`) and a contract test pins the strings to `events` (Task 6). |
   | `secret` | `errors fmt os strings` | No (`os`). Only `env.go` and `main.go`. |
   | `outbox` | pgx, pgxpool, prometheus, kafka-go, `pkg/metrics`, `pkg/tracing`, ... | No. `outbox.Add` is the Postgres adapter's; `outbox.NewRelay` is `main`'s. |
   | `eventcodec` | `net/http`, `crypto/tls`, `hamba/avro`, `pkg/events`, `pkg/secret`, `os`, ... | No. Behind the `Encoder` port. |
   | `auth` | `net/http`, `crypto/*`, `jwt`, `pkg/secret`, `os`, ... | No, **including `auth.Limiter`**: it lives in the same package as the verifier, so the public-lookup rate limit stays in the HTTP adapter (Decision 8). |
   | `migrate`, `health`, `serve`, `tracing`, `metrics`, `logging`, `kafkaconn` | I/O, HTTP or environment | No. Adapters or `main` only. |

   `app` may import: the standard library minus the banned I/O packages, `github.com/google/uuid` (the `eventId` of the announced event, minted exactly where `queueReview` mints it today), and `grab-mini/profile-service/internal/domain`. **Verification, run in Task 9 and whenever `app` changes:** `go list -f '{{range .Imports}}{{println .}}{{end}}' ./internal/app | grep -E '^(grab-mini|github|golang|google)'` prints exactly `github.com/google/uuid` and `grab-mini/profile-service/internal/domain`. `archtest` checks direct imports only; `uuid` itself imports `net` and `os`, so no transitive "app is free of I/O" claim is made.
2. **Resync is a use case with ports, not an adapter detail.** It carries rules and sequencing that two entry points (`POST /driver-applications/resync` and `profile-service resync`) share and that are the reason the flat tests exist: one run at a time across instances, batching of 200 with one transaction per batch, status re-read under the row lock (a driver who became PENDING since the id list was read is skipped), dating via `nextReviewTime`, the `resync` reviewer and reason fallback, counts added only after commit, three run results counted. Leaving it in an adapter would put a state-machine rule next to SQL again. Ports (small, all in `app`): `ResyncLocker{ TryLock(ctx) (unlock func(), acquired bool, err error) }` (session advisory lock on a connection the adapter holds; `unlock` detaches from `ctx`, runs `pg_advisory_unlock` with a 5 s timeout, closes the connection instead of returning it when that fails, then releases it), `ResyncSource{ ResyncableIDs(ctx, after string, limit int) ([]string, error) }`, plus the shared `DriverReader` and `UnitOfWork`. `ResyncBatch = 200` and `ResyncTimeout = 15 * time.Minute` are `app` constants (policy); the lock key `0x726573796e63` is a Postgres detail and lives in the adapter (exported as `postgres.ResyncLockKey` because `TestOnlyOneResyncRunsAtATime` takes the same lock from outside). The use case returns the partial `ResyncResult` together with the error (the CLI prints `res.Total` in its failure line).
3. **One `UnitOfWork.Do(ctx, fn func(Tx) error) error`; each use case keeps the exact order of the flat transaction.** `Do` begins, runs `fn`, commits when `fn` returns nil and rolls back otherwise (the old `defer tx.Rollback`). `Tx` is narrow and mirrors the four distinct statements, so SQL text does not change: `LockOrCreateDriver(ctx, id, now) (domain.Driver, error)` (`INSERT ... ON CONFLICT DO NOTHING` then `SELECT ... FOR UPDATE`), `LockDriver(ctx, id) (domain.Driver, error)` (`domain.ErrNoDriver`), `UpdateProfile(ctx, domain.Driver) error` (saveDriver's 13-column UPDATE), `MarkPending(ctx, id string, now time.Time) error` (apply's UPDATE), `RecordReview(ctx, d domain.Driver, at time.Time) error` (review's UPDATE: `reviewed_at = at`, `status_at = updated_at = d.StatusAt`), `QueueReview(ctx, driverID string, payload []byte) error` (`outbox.Add(ctx, tx, source, events.TopicDriverApplicationReviewed, []byte(driverID), payload)`). Orders, taken from the flat code and pinned by a recording fake (Task 4 and 5):

   | Use case | Order inside `Do` | After a successful commit |
   |---|---|---|
   | `SaveDriver` | clock read `now` **first** (before the lock), `LockOrCreateDriver(now)`, incomplete check (only when status is not NONE; missing `vehicleType` before `plate`), compute `changedVehicle`, mutate; if changed: clock-derived `at = NextReviewTime(d.ReviewedAt, now)`, **encode, `QueueReview`, then** `UpdateProfile` | counter `Review("vehicle_changed")` and `Wake` only when changed; then (in the use case, after `Do` returns) `Updated("driver")` and the log line |
   | `Apply` | `LockDriver` (`ErrNoDriver` becomes `ErrNoProfile`); PENDING or APPROVED returns unchanged (nothing written: the flat code never committed, an empty commit is indistinguishable); SUSPENDED refused; missing list in the order name, vehicleType, plate; **then** clock read; `MarkPending` | `Application("submitted")` and log; replay path `Application("replayed")`, no log, no wake; apply never wakes |
   | `Review` | `LockDriver`; transition check; **then** clock read; `at = NextReviewTime`; `RecordReview` **then** encode and `QueueReview` (the reverse of SaveDriver: both are kept as they are) | `Review(decision)`, `Wake` (always), then the log line `driver %s: %s by %s -> %s` |
   | `Resync` batch | clock read once per batch **before** the loop, then per id `LockDriver`; skip when `ErrNoDriver` or not resyncable; `NextReviewTime`, reason fallback, reviewer, encode, `QueueReview` | counts and `ResyncEvents(status, n)` added, `res.Skipped` added, **`Wake` even when the whole batch was skipped** (the flat code wakes after every committed batch) |

   Consequences to keep and pin: the encode runs **inside** the transaction, while the driver row lock is held (ADR 0014's "encode before the transaction" does not apply here, as in promotion-service; see Known, not fixed); an encode failure rolls the decision back (`TestTheEventIsNotPublishedWhenItCannotBeQueued`) and its error text is `encoding the review result: <err>` (wrapped in the use case, not the adapter); the clock is read **after** the row lock in `Apply` and `Review` and before it in `SaveDriver`; both `Truncate(time.Microsecond)` and `UTC()` are applied by the use case's `now()` helper exactly as `s.now().UTC().Truncate(time.Microsecond)` today.
4. **Metrics: `app.Metrics` for the six counters the use cases touch, a separate tiny interface for the one the HTTP adapter touches.** `app.Metrics{ Updated(kind string); Application(result string); Review(decision string); PublicLookup(result string); ResyncEvents(status string, n int); ResyncRun(result string) }`. `profile_requests_rejected_total` is incremented only by `refuse`, the 429 branch, and nowhere else, so it is an HTTP concern: `adapters/http` declares `Refusals interface{ Refused(code string) }`. `adapters/metrics.Metrics` implements both; `metrics.New()` returns a wrapper over **package-level** `promauto` vars (it registers nothing itself, so calling it twice, from `main` and from a CLI path, cannot panic). Names, label names and help text are copied character for character (Task 1 records them, Task 6 compares). Tests read counters through `prometheus.DefaultGatherer` with a small helper, so the vars stay unexported.
5. **The use cases take plain types and own the order of refusals.** The HTTP adapter does transport only: identity (`auth.From`, `auth.Deny(401, "missing bearer token")`), the own-profile rule (`own`: path id must equal the token subject, else 403 `forbidden` whether or not the profile exists; it uses `auth.Identity`, so it stays in the adapter, too small to be domain), the 8 KiB `io.LimitReader` JSON decode and its `invalid JSON body` answer (an empty body is accepted for review and resync only), query and path extraction, views, status codes. Commands carry the raw strings: `SaveRiderCommand{ID, Name, Phone}`, `SaveDriverCommand{ID, Name, Phone, VehicleType, Plate, Model, Color}`, `ReviewCommand{DriverID, Action, AdminID, Reason}`, `ListQuery{Status, Limit, Cursor}` because the refusal order is behaviour: rider name before phone; driver name, phone, vehicle, plate, model, colour; review reason (400) **before** the id check (404) **before** the transaction; list status, then limit, then cursor. Cleaning is `domain.Clean*`; errors are `*domain.FieldError` (`Error()` is `field: msg`, and the 400 body's `error` is exactly that text, `field` is the field name), `*domain.IncompleteError{Missing []string}`, `*domain.TransitionError{From, Action}`, `*domain.InvalidRequestError{Message}` (list filters), sentinels `ErrNoDriver`, `ErrNoProfile`, `ErrSuspended`, `ErrResyncRunning`. `GetRider` returns an empty `Rider{ID}` (no error) for a rider with no row, as the handler does today.
6. **Error labels belong to the adapter that knows the call.** Unlike promotion-service, the flat code labels an internal error per handler, not per step (`load rider <id>`, `save rider <id>`, `load driver <id>`, `save driver <id>`, `apply driver <id>`, `<action> driver <id>`, `load public driver` without the id, `list driver applications`, `resync`). The use cases therefore return port errors unwrapped (except the encode wrap in Decision 3) and the HTTP adapter's `internalError(w, what, err)` keeps its `"%s: %v"` log format and its `{"code":"internal","error":"internal error"}` body (and `profile_requests_rejected_total` is **not** incremented for it, as today). No `StepError` is introduced.
7. **Views, the NONE fallback and the time zone stay in the HTTP adapter.** `riderView`, `driverView`, `adminDriverView`, `publicDriverView` keep tags and field order; a driver with status `""` is shown as `NONE`; `updatedAt`/`statusAt` are `null` when `UpdatedAt` is zero (a rider or driver who never saved one: 200, not 404). `scanDriver` converts every timestamp to UTC and the rider's `updated_at` too, in the Postgres adapter (unlike promotion-service, nothing here depends on `time.Local`); the golden tests do not need to pin `time.Local`, but keep a row that shows a `Z` offset. `reviewedBy` appears only in the admin view; the public view has no phone and no status.
8. **The public-lookup rate limit stays in the HTTP adapter and is built by it.** `http.NewPublicLimiter(perMinute int) *auth.Limiter` is the old `newLimiter` (burst `max(1, perMinute/4)`, rate `perMinute/60`, `auth.LimiterFromEnv`, so `RATE_LIMIT_SCALE` is read when it is built); `main` calls it with `env.PublicRatePerMinute` and passes the result to `http.NewAPI(svc, verifier, limiter, refusals)`; a nil limiter lets everything through (the test fixture). Order in `handlePublic` is kept: identity 401, **limiter 429** (counts `rate_limited` as a refusal, sets `Retry-After`), then the lookup, then 404 for "missing or not APPROVED" (counts `PublicLookup("not_found")` in the use case and `not_found` as a refusal in the adapter, in that order). The use case `PublicDriver(ctx, id)` returns `domain.ErrNoDriver` for both missing and not approved.
9. **Test databases.** The flat tests truncate `rider_profiles, driver_profiles` and `DELETE FROM outbox WHERE source = 'profile-service'` on `TEST_DATABASE_URL`. After this migration there are three DB-backed test packages (`adapters/postgres`, `integration`, and the root package until Task 8). Each of the two new ones gets a `testdb_test.go` copied from `services/order-service/internal/integration/testdb_test.go` (package, prefix `profiletest_<package>_`, and `migrations()` to `os.DirFS("../..")` or `"../../.."` by depth; `postgres.Connect` takes `fs.FS`), one database per test, dropped `WITH (FORCE)`. Advisory locks are per database, so private databases also make the resync lock tests independent of each other. A `profiletest_*` database left over after a run is a bug.
10. **Subcommands and seed.** `runMigrate`, `runSeedDev`, `runResync` stay in `main.go` with every `log.Fatal*`, the `flag` set, the `fmt.Fprintf(os.Stdout, ...)` line and exit paths unchanged; they call `postgres.Migrate`, `postgres.SeedDev(ctx, pool) (drivers, riders int, err error)` and `app.Service.Resync`. `postgres.SeedDev` keeps the same SQL, the two literal tables of dev data, `time.Now().UTC().Truncate(time.Microsecond)` and `ON CONFLICT ... DO NOTHING`; no use case, no port (one caller, dev only). The `secret.Development()` guard and the log text stay in `main.go`. The CLI builds a full `app.Service` with `Relay` an **untyped nil** (it only queues; the running service's relay publishes) and `Now` nil (defaults to `time.Now`).
11. **The Avro-side adapter is `adapters/kafka`, with an encoder only.** There is no consumer, so the adapter is one file: `kafka.NewEncoder(Codec) *Encoder` implements `app.Encoder`, maps `app.ReviewedEvent` to `events.DriverApplicationReviewed{Envelope{EventID, OccurredAt: t.Format(time.RFC3339Nano)}, DriverID, Status, VehicleType: events.VehicleType(v), Reason, ReviewedBy}` and encodes on `events.TopicDriverApplicationReviewed`. **`OccurredAt` is formatted from the time as given, with no added `.UTC()`** (the flat code formats `at`, which is already UTC; adding a conversion would be an unpinned edit). `Codec` is the one-method `Encode(ctx, topic string, v any) ([]byte, error)` interface that `*eventcodec.Codec` satisfies; the integration tests' `jsonEncoder` and `failingEncoder` are `Codec`s. Name kept as `kafka` to follow the ADR layout; the package comment says it holds no consumer because the service consumes nothing.
12. **Splitting a test: every assertion gets a named home.** Task 1 writes `baseline.md` with an **assertion inventory**: one line per golden row and per distinct assertion of the old tests that Tasks 6 to 8 will split (error bodies, headers, log lines, counter deltas, outbox rows, payload fields, "logs nothing" assertions, "no row changed" assertions). Task 8 step 2 greps each line in its new home and reports the table. `TestPersonalDataIsNeverLogged`, `TestResyncNeverLogsPersonalData` and `TestResyncRepublishesTheCurrentStatusOfEveryEligibleDriverAndChangesNoRow` move **whole** to `integration` and are also mirrored (not replaced) at app level over fakes.
13. **Test fixture changes, mechanically.** The flat tests mutate the service after building it (`f.svc.enc = ...`, `f.svc.relay`, `f.svc.now`, `f.svc.publicLimiter`). The integration fixture keeps `enc`, `relay`, `limiter` fields and a `rebuild()` that builds `app.Deps` and `http.NewAPI(...).Routes()` again; each mutation site (`integration_test.go` lines 469, 474, 793, 908, 912; `resync_test.go` 244, 247; `kafka_integration_test.go` 103, 112) becomes `f.useEncoder(x)`, `f.useRelay(r)`, `f.useLimiter(l)`. The clock stays a closure over `f.now`. `profileRows()` (uses `driverColumns` and `scanDriver`) becomes a raw `SELECT * FROM driver_profiles ORDER BY driver_id` formatted from `rows.Values()`, which is at least as strong ("no row changed").

## Review Focus

Behaviour the ADR implies and the existing tests do not fully pin; each has a test in the owning task.

1. **Response bytes and headers, exact.** Every response goes through `writeJSON`: `Content-Type: application/json`, `Cache-Control: no-store`, `json.Encoder` output (map keys sorted: `code` before `error` before `field`/`status`; trailing newline). 401 and 403-from-verifier come from `auth`. Pinned by the golden table of Task 1 and asserted again in Task 7.
2. **Order of refusals** (Decision 5): own-profile 403 before JSON 400 before field 400s in a fixed field order; review: reason 400 before bad-id 404 before 404 no driver before 409; list: status, limit, cursor; resync: identity, body, driverId shape 404, lock 409, existence 404 (not counted as a run). Pinned in Task 1 (golden) and in Tasks 3 to 5 (use cases).
3. **Counters and logs only after a successful commit**, wake after commit, and which paths wake (Decision 3 table: SaveDriver only when the vehicle changed, Review always, Resync after every committed batch, Apply and SaveRider never). The flat tests cannot observe `Wake` (the relay is a concrete `*outbox.Relay` and the fixture passes nil), so it is pinned **from the flat code** in Tasks 4 and 5 with a fake `Waker`; Task 1 records the reading in `baseline.md` as a table with line numbers.
4. **Concurrency on one driver.** The row lock (`FOR UPDATE`) is taken before the status check and before the clock where the code does so; `nextReviewTime` uses the locked row's `ReviewedAt`. The old tests (`TestConcurrentDecisionsOnOneDriverHaveOneWinner`, `TestConcurrentVehicleChangesAndDecisionsKeepTheEventsInOrder`, `TestResultTimesIncreaseEvenIfTheClockStepsBack`) run unchanged in Task 8, plus a call-order test in Task 4.
5. **Encode inside the transaction.** A failing encoder leaves the status unchanged and nothing in the outbox; a fake `UnitOfWork` records the order of calls.
6. **Resync lock lifecycle.** The lock is taken on a held connection and released on a context that survives the caller's cancellation; the lock is released after every run including failures; a refused run counts `refused_running` (and the HTTP 409 counts `resync_running`), an unknown single driver counts **no run at all**; `res` is returned with the error.
7. **Typed-nil `Waker`.** The flat `wake()` checks `s.relay != nil` on a `*outbox.Relay`. A nil `*outbox.Relay` stored in an `app.Waker` is a non-nil interface and would panic. `main` always passes a real relay; tests and the CLI pass an untyped nil `Deps.Relay`; the use case checks `s.relay != nil`. Never build a `Waker` from a possibly-nil pointer.
8. **Admin queue.** Oldest `status_at` first, tie broken by `driver_id`; the cursor is `<UnixMicro>.<id>` (the adapter parses it with the same messages; `5.` and `-1.x` and an id over 128 bytes are refused); the page is fetched with `limit+1` and trimmed; `applications` is `[]` not `null` when empty; `nextCursor` is `null` or a string.
9. **Personal data.** No log line, error text or `%+v` carries a name, phone, plate, model or colour (including the SQL errors that `internalError` logs, which hold no row data today). `TestPersonalDataIsNeverLogged` runs whole in `integration`; Task 4 repeats it over fakes with log capture.

## Known, not fixed (report, do not change)

- The Avro encode of `driver.application.reviewed` runs inside the transaction, holding the driver row lock (and, for resync, up to 200 of them); a slow Schema Registry lengthens the lock. Kept as it is; the follow-up is not mechanical because the encode needs the post-change row.
- `handlePublic` loads by the raw path id with no length or UTF-8 check (the review and resync paths check it). A very long or non-UTF-8 id is probably a 500 `load public driver` rather than a 404; Task 1 records what it does, the migration keeps it.
- `profile-service resync` (CLI) prints no `resync by ...` log line; only the HTTP path logs it. Kept.
- Review routes are registered by ranging over a map, so registration order is random (harmless, Go's mux matches by specificity). The migration registers them from a sorted list; this is not observable.
- `ListApplications` rows are scanned into memory (at most 101); `resync` of a very large fleet can outlast the server's write timeout (documented in the handler comment).
- No retention for profiles (documented in production-design.md).
- Any test found to be order-dependent or to depend on the shared `TEST_DATABASE_URL` beyond what Decision 9 fixes.

## Decisions taken instead of open questions

Each is a recommendation the plan has already applied; the user can overrule any of them before Task 2 starts, and none blocks Task 1.

1. **Resync is a use case with a lock port (Decision 2), not an adapter helper.** Cost: two small ports and a fake in tests. Alternative rejected: leaving `resync` in `adapters/postgres` would move the batching, skip and dating rules next to SQL again and make the resync rules testable only through Postgres.
2. **`pkg/auth`'s limiter stays in the HTTP adapter.** Alternative rejected: a `RateLimiter` port in `app`; the limit is a transport policy (per caller, in memory, per instance) and its refusal is an HTTP 429 with a header, so a port would have one caller and no domain meaning.
3. **`domain.VehicleType` instead of `events.VehicleType`.** One duplicated 3-line type, pinned by a contract test, so `domain` and `app` import nothing from `pkg`. Alternative rejected: allow-listing `pkg/events` for this service, which ADR 0014 forbids on purpose.
4. **`adapters/kafka` holds the encoder only.** Alternative rejected: folding the event mapping into `adapters/postgres`, which would make the Postgres adapter depend on the wire contract.
